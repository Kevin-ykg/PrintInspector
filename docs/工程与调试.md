# 工程与调试

## 工程地图

| 目录或入口 | 内容和定位方式 |
|---|---|
| [PrintInspector.sln](../PrintInspector.sln)、[build.ps1](../build.ps1) | IDE 和脚本使用同一解决方案，均支持 Debug、Release 的 x64 配置 |
| [desktop](../desktop) | [MainWindow.xaml](../desktop/MainWindow.xaml) 定义两个画框和操作按钮。MainWindow.xaml.cs 负责目录、模型选择、批量处理、视图变换。Engine.cs 负责 BMP 解码、DLL 调用和轮廓生成 |
| [native](../native) | print.hpp 定义 ABI，print.cpp 负责配准、特征和投票，refine.cpp 负责得到最终掩膜 |
| [models](../models) | settings.json 记录路线、维数和阈值，rf*.yml 是 OpenCV 模型。rf2、rf3 为 PCA 对照候选 |
| [third_party/opencv](../third_party/opencv) | 工程自带 OpenCV 4.5.4 的头文件、导入库、运行库和许可 |
| [evaluation](../evaluation)、[results](../results) | Python 训练与验证入口、固定选区、分组配置及评估输出。当前数据结果在 results/无膜片 |
| annotation-drafts、experiments | 候选标注、不同训练配置的历史对照。校订后的参考图放在 references/<编号>.png |
| archives、build、desktop/bin、desktop/obj、.vs | archives 保留旧工作站和历史发行快照。当前 VS 产物在 build/vs 和 desktop/bin。旧 CMake 缓存含搬迁前路径，若另用 CMake 应指定新的空构建目录 |

原始图库和硬件 PDF 位于此工程文件夹的上一级，可直接在 WPF 中选其他图库，不需要复制原始照片。

## 操作和代码如何对应

| 操作 | 从哪段代码开始跟踪 | 应观察到的结果 |
|---|---|---|
| 打开目录、点击样品 | MainWindow.OpenFolder → GroupChanged → ReadBand | 样品列表按编号排序；换组时清理上一组的结果，原图定位恢复适应画框 |
| 单组与批量 | SingleClick 或 BatchClick → Run → Engine.Run → ms_run | 单组刷新右框；批量先选择目标目录，共用模型句柄，按编号写出已完成的组。取消后可在所选目录查看已保存结果 |
| 切换得分、掩膜或轮廓 | MainWindow.Render → ResultView / Edges | 分析同一位置时只切显示图层。切换模型后应重新运行 |
| 同步缩放、平移 | ZoomAt、PanBy → ApplyView | 共用原图像素中心；显示使用 WPF DIP。双击复位，导出始终保留原始分辨率 |
| 保存结果 | Engine.Save | mask.png 可计数；score.png 是原始票率；overlay.png 以 W 为底；status.txt 包含复核状态、原生耗时、分类阈值和实际使用的掩膜参数 |

[窗口布局](../desktop/MainWindow.xaml) 将选样、选模型和运行集中在左栏；两个画框各自的选择框就在画框标题旁。底栏保留运行状态和当前结果导出。按钮样式、键盘焦点和字号在 [App.xaml](../desktop/App.xaml)；应用与窗口使用 [多尺寸 ICO](../desktop/Assets/PrintInspector.ico)。图标由内置 ImageGen 生成，设计提示为深青底的白色 T 恤，胸前用青绿、青蓝、琥珀三条印花表示不同波段，轮廓简洁以适应小尺寸。[当前界面](../results/无膜片/界面.png)

## 构建与断点

1. 安装 VS 2026 的「使用 C++ 的桌面开发」和「.NET 桌面开发」工作负载，使用 MSVC v145、Windows SDK 10.0 和 .NET 10 SDK。构建配置见 [PrintVision.vcxproj](../native/PrintVision.vcxproj)、[PrintInspector.csproj](../desktop/PrintInspector.csproj)。
2. 打开解决方案，选 x64，在 WPF 工程设为启动项目后按 F5。打开「属性管理器」可查看 [OpenCV.props](../native/OpenCV.props)。该属性表从工程相对路径加载 include 及 x64/vc15/lib，Debug 链接 opencv_world454d，Release 链接 opencv_world454。
3. WPF 的 ProjectReference 先生成原生工程，CopyNativeRuntime 把 DLL、OpenCV 运行库和原生 PDB 复制到 desktop/bin/x64/<配置>/net10.0-windows，模型位于该输出目录的 models 子目录。混合调试已在 Properties/launchSettings.json 启用。在 Engine.Run、ms_run、refineMask 下断点，运行同一组样品即可跨语言跟踪。
4. 发现 DLL 加载失败时，在「调试 → 窗口 → 模块」核对实际加载路径、x64 架构和 PDB。更改 settings.json 或替换模型后重新生成，再检查输出目录中的副本。

在这一层工程目录运行以下命令可复现 IDE 的构建。

```powershell
.\build.ps1 -Configuration Debug
.\build.ps1 -Configuration Release
```

## 改动后的验证

研究脚本使用 Python、NumPy、Pillow 和 Python OpenCV。按下列顺序执行，最后一条会生成全组报告。WPF 验证使用实际渲染控件，benchmark 统计读盘至离屏渲染。benchmark 与 review 宜分别单独运行以测量节拍。

```powershell
python -B evaluation/check_abi.py
python -B evaluation/check_refinement.py
python -B evaluation/review.py
python -B evaluation/compare_fabric.py
dotnet desktop/bin/x64/Release/net10.0-windows/PrintInspector.dll --ui-smoke ../锐视光电 results/无膜片/界面.png
dotnet desktop/bin/x64/Release/net10.0-windows/PrintInspector.dll --benchmark ../锐视光电 results/无膜片/benchmark.csv
python -B evaluation/report.py
```

PRINTVISION_DATA 指定包含编号子目录的输入集合，PRINTVISION_RESULTS 指定评估输出。compare_fabric.py 使用随附无膜片样品的固定坐标及 previous-masks 基线。C++ 使用根目录 .clang-format，C# 使用 dotnet format whitespace，evaluation 中的 Python 使用 Ruff 格式化。格式检查应限定项目源码，历史产物、第三方代码及训练模型单独保存。
