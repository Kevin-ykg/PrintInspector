# 新硬件实拍与自适应布底分割

## 从界面复核样品

打开“锐视光电/没有膜片”，选当前编号 1～5，在右侧分割方法中选择“自适应布底”，点击“运行当前组”。先看轮廓叠加，再放大看二值掩膜中的小字、字孔、裸布和渐变边缘。前景得分图的亮度表示该处偏离本件衣服裸布的程度。右侧「掩膜参数…」可调整前景阈值、去噪面积上限和小点保护分差，默认分别为 128、96 像素和 32。点「应用并重跑」后对比同一处裸布与细小印花。批量沿用本次选择的路线和参数，导出时将参数写入 status.txt。

## 为什么换硬件后森林会退化

两种森林都用训练样品确定分裂条件。当前模型训练使用历史照片的图案与裸布标注；即使森林用上了相对灰度，同一油墨换到另一套光源、曝光和相机上，八维响应的位置和各通道强弱关系仍可能改变。图像尺寸也从旧组的 2448×2048 灰度变为新组的 5472×3648 RGB，纹理窗口覆盖的物理面积可能随视场改变。原来能把前景和背景分开的条件在新图上可能同时命中裸布，也可能漏掉油墨。新组存在与旧训练集同属冲浪图文的款式，简单归因于“没见过这个图案”会忽略采集条件的变化。

PCA 森林先用训练时冻结的投影把八个波段压缩到四维，某些通道漂移可能恰好在保留下来的组合里影响较小。也可能丢掉区分某种油墨所需的方向。仅凭五组实拍无法分离硬件、曝光、布料与款式各自的贡献。将这五组加入训练后再在原图测精度，只能衡量对已见样本的适应。

## 从参考工作台吸收的实现

| 阶段 | 在当前项目中的实现 |
|---|---|
| 解码与对齐 | WPF 按通道名载入。自适应路线对 24 位各波段取 RGB 均值，森林使用训练时的 BT.601 亮度。C++ 沿用 W 坐标配准，仅在八帧共同覆盖区计算。 |
| 估计“这里本来是什么布色” | 在原图上布设网格，分层取样并计算各波段中位数。在对数亮度空间迭代拟合各波段的平滑背景曲面，降低疑似油墨的权重，再用可信邻域修正局部光照渐变。 |
| 区分油墨与布纹 | 用裸布样本估计八维残差的中心与协方差。对每个像素，比较实测光谱与该处预测布底，以正则化的马氏距离衡量偏离。同样大小的变化，沿常见布纹方向的分数会低于沿罕见光谱方向的分数。 |
| 形成掩膜 | 将距离乘 22.5、量化为 0～255 的分数，对满足局部反差条件的深色笔画精化光晕，再与前景阈值（默认 128）比较。前景掩膜按八邻域分组。弱孤点按面积及局部证据筛选，具有连续响应的细长笔画有独立保护。 |
| 控制开销 | C++ 接收上位机已解码的八帧，使用并行行带和滑动窗口。每个行带只维护逐列累加值与当前行的光谱。八帧共同视野受位移或行步长影响时，按需复制为连续缓冲区。 |

算法主体在 `native/fabric/segmentation.cpp`，深色笔画精化在 `native/fabric/refinement.cpp`。入口 `native/print.cpp::ms_run_fabric` 返回掩膜、得分、位移、状态与耗时；WPF 通过 `desktop/Engine.cs` 调用。该路线无需森林模型，也无需部署工作台。空间拟合需要足够的代表性裸布。满版图案、多色拼布、大褶皱、强反光都可能破坏该假设。当可信拟合锚点少于 10 个或占候选锚点不足 20% 时，界面提示“底布参照不足”。该标志用于筛查，未触发仍可能有分割错误。

## 五组实拍怎样比较

下表是引入孤点过滤前的基线。所有路线使用当前编号 1～5 的同一份八通道文件。复核点来自参考工作台在原始波段上选定的笔画、字孔和裸布点；裸布统计区统一取横向 90%～98%、纵向 10%～90%。这块矩形只用于这五组的离线评价，算法没有按位置屏蔽这一带。逐像素 IoU 在此处衡量两份软件输出的一致程度，整图质量仍需人工真值。

| 检查项目 | 八波段森林 | PCA 森林 | 自适应布底 | 参考工作台 |
|---|---:|---:|---:|---:|
| 符合预选复核点 | 41/44 | 42/44 | 44/44 | 44/44 |
| 2 号右侧裸布误提像素 | 338 | 232 | 0 | 0 |
| 3 号右侧裸布误提像素 | 0 | 0 | 153 | 139 |
| 4 号与参考工作台的掩膜 IoU | 0.5452 | 0.9197 | 1.0000 | 1 |
| 5 号与参考工作台的掩膜 IoU | 0.4635 | 0.9010 | 0.9974 | 1 |

1 号的小字上，两条森林都只通过了 13 个检查点中的 11 个。5 号两条森林均通过全部 8 个检查点，整幅掩膜却有明显分歧，说明稀疏抽查会漏掉大区域差异。自适应布底与工作台有共同的算法来源，这五组也是工作台已用过的样品，不能用它们给出未知批次的生产精度。

Release x64 在本机逐组各跑一次，五组纯算法时间的中位数分别为八波段森林 1324 ms、PCA 森林 2058 ms、自适应布底 367 ms、工作台 751 ms。当前 DLL 计入原生配准；工作台采用自己的 segment_ms 计时。两者均排除读盘、解码、WPF 显示和磁盘导出。详见[逐组数据](../results/跨硬件/实拍对照.csv)和[五组原图与掩膜](../results/跨硬件/五组对照.jpg)。

**复现。** 先构建本工程和参考工作台的 Release x64，在本工程根目录运行 `python evaluation/compare_hardware.py`。脚本需 Python 3.11 或更高版本、NumPy、Pillow、OpenCV Python，以及同级数据目录下参考工作台的 Release DLL 和复核点定义。输出表与对照图写入 `results/跨硬件`。仅本次跨项目对照依赖参考工作台。WPF 或 Visual Studio 中运行自适应布底无需此依赖。

历史报告沿用原始编号。当前目录 6、7、8、9、10、11、12、13 分别对应历史 2、7、8、4、5、11、12、15。离线训练和复核通过 W.bmp 的 SHA-256 恢复这八组的样品身份，避免把同编号的旧笔画标注套到新布料上。新增样品须独立建档和标注后才能加入历史训练集。本次对两条森林重跑 6～13，逐组核对原分辨率二值掩膜和前景得分，16 组输出均与历史存档逐像素一致。

同样用自适应布底反测旧设备时，发现当前 6、7、9 号的已知空台面选区被整块判为图案。布底残差能发现与衣服不同的材料，台面也符合这个条件。后续版本将森林的黑台面识别接入自适应布底，复测见下节。[旧设备逐组复测](../results/跨硬件/旧设备自适应复测.csv)

## 自适应布底去噪复测

在相同的五组实拍上保持前景阈值为 128。默认去噪面积 96 像素、保护分差 32，使整幅掩膜的八邻域前景连通域合计由 5953 降至 835，人工预选的 44 个复核点均通过。连通域总数包含真实图案碎片，用来描述掩膜中孤立区域的数量。3 号右侧裸布选区仍有 127 个误提像素，原基线为 153；把面积和分差分别调至 128 和 80 时，降至 88 个。较强设置只在这五组做了复核点检查。

Release x64 单次逐组测量中，五组 DLL 时间中位数由 345 ms 增至 382 ms。去噪启用时，全分辨率标签图约占 76 MiB，另有连通域统计的临时开销；该版本尚未重测 WPF 进程峰值。详见[逐组去噪数据](../results/跨硬件/自适应去噪复测.csv)及[调参步骤](分割故障排查.md)。

## 弱笔画与黑台面复测

黑台面识别与随机森林共用。把和画框相连、八波段均很暗的区域排除出布底曲面与噪声采样，再清理几乎整条贴着台面的细长假轮廓。默认参数下，当前编号 6、7、9 的三个固定台面选区分别从 29,820、43,834、38,970 个误提像素降到 0。8 号的固定选区由 42 降到 15；12 号目视对照中的长布边线已去掉，历史局部标签 IoU 由 0.8383 变为 0.8372。

孤点过滤增加了连续弱笔画保护。同样是只在一个波段中比布底亮 19 个灰度级的合成样本，面积 128、保护分差 80 的设置下，旧版删除细线和孤点，新版保留细线的 46 个有效前景像素，孤点仍被过滤。可运行 `python evaluation/check_fabric_strokes.py` 复核。新硬件五组在默认和较强去噪设置下均通过 44 个预选点，3 号的右侧固定裸布区从 127 个误提像素降至 0（默认设置）。这批数据缺少全图真值，低响应的短笔画、孤立印点和贴着台面的真实细线仍需抽查。Release x64 单次逐组对照中，新硬件五组的默认 DLL 时间中位数从约 0.43 秒增至 0.63 秒。

## 从读盘到 WPF 预览

新设备每件有八幅 5472×3648 的 24 位 BMP。测得通用 WPF 解码是端到端的主要开销。自适应路线现在对无压缩 BGR24 按行块读取，复用一张灰度工作图，把每帧交给本组原生缓冲区，完成后统一释放。索引色等其他编码仍走 WIC。预览取同一灰度定义。解码测试覆盖正负 BMP 高度、行填充和非灰色像素。

以下是引入孤点过滤前的解码性能基线。在本机对当前 13 组连续跑两轮，其中新设备五组共十次。使用相同自适应算法，读盘到 WPF 离屏绘制的中位数从 2.88 秒降到 0.96 秒，读盘和转换阶段从 2.37 秒降到 0.39 秒。全程每 30 ms 采样的进程峰值私有内存由 793.5 MiB 变为 830.8 MiB。计时包含轮廓生成与绘制，不含文件导出、相机采集和物理屏幕刷新。运行 `PrintInspector.exe --fabric-benchmark "<无膜片目录>" "<输出CSV路径>"` 可在生产机重复此测量。表内 route=0 表示自适应布底。[通用解码记录](../results/跨硬件/WPF通用解码.csv) · [优化后记录](../results/跨硬件/WPF运行.csv)

## 锐视 3 号左侧字母修复

锐视「没有膜片」3 号和「多光谱」2 号均是左侧带 `RETURN TO LIBRARY` 的暗布样品。旧版黑台面候选与画框相连，覆盖约 41% 的画面，使真实暗布退出拟合和噪声估计，左侧字母内部响应偏弱。调整掩膜参数只能改变后续二值化和孤点筛选。

自适应路线新增一项校验。候选区至少一半像素的八波段最大值需在 20 灰度级或以下，才确认为台面。证据不足时保留暗布并提示复核。两份样品在相同默认掩膜参数下输出一致，左侧字母选区与参考工作台的 IoU 从 63.11% 提升至 96.58%，全图从 88.58% 提升至 97.23%。相同右侧裸布选区由 0 增至 127 个误提像素。锐视 6～13 的掩膜逐像素一致，多光谱目录 3 号的掩膜也逐像素一致。这些数据衡量与参考工作台的输出重合度。

## 如何在生产前验证泛化

1. **先做配对采集。** 用相同衣服、相同图案在两台设备各拍一组，保留波段映射、曝光、增益、照明几何和像素对应的物理尺寸。有条件时同步采集暗场、白参考与同材质裸布。这样才能区分机器变化、服装变化和尺度变化。
2. **按实际使用场景留出测试。** 同一款、同一布料批次的连拍必须放在同一侧。分别留出整款图案、整批布料和独立采集时段。若要宣称支持全新硬件，需再留出整台设备；若只部署到已校准的固定设备，则应验证这台设备的未见批次。阈值和模型在测试前冻结。
3. **用带物理意义的指标验收。** 对未知组制作全分辨率掩膜，对归属不确定区域作忽略标记。逐组统计 IoU、漏提、误提、边界偏差，专门量小字笔画、设计孔洞、孤立墨点和裸布区域，报告最差组。结合业务允许的最小缺陷尺寸、良品重复拍摄波动以及真实漏烫/多烫样品，确定可接受的误报、漏报和节拍。
4. **把失败保留为证据。** 生产时记录采集配方、路线版本、得分图和复核状态。优先复核底布参照不足、波段对齐不稳、或两条路线明显分歧的工件。把已确认失败的样品加入下一轮开发，同时保留独立盲测批次。两条路线对同一块区域同时漏提时，同样需要靠抽检发现。
