# 分割耗时与内存验证

## Release x64 实测

在 Intel Core i7-14650HX（24 个逻辑处理器）上，使用锐视「没有膜片」的全部 8 组样品，每组 8 张 2448 × 2048 的 BMP。旧版来自提交 `3ee6828`。两版都在 Visual Studio 调试器外运行，采用相同模型、掩膜参数、样品顺序和离屏绘制尺寸。每次启动一个 WPF 进程，先运行四维 PCA 一轮，再运行八波段两轮。两轮八波段包含同一批样品的重复观测。

| 路线（观测次数） | DLL 中位耗时 | DLL P95 | 读盘到预览中位耗时 | 读盘到预览 P95 | 进程峰值私有内存 |
|---|---:|---:|---:|---:|---:|
| 八波段（16），优化前 → 后 | 3703 → 432 ms | 4430 → 514 ms | 4012 → 551 ms | 4782 → 638 ms | 339.0 → 298.7 MiB |
| PCA（8），优化前 → 后 | 4306 → 671 ms | 4698 → 823 ms | 4612 → 780 ms | 4981 → 938 ms | 327.2 → 269.1 MiB |

计时从读取第一张 BMP 开始，到 WPF 完成 960 × 402 的离屏渲染为止。模型加载、显示器刷新、相机采集、批量导出 PNG 的磁盘写入另计。峰值为各路线运行期间每 30 ms 采样的进程私有内存最大值，包含托管堆、OpenCV 和 WPF，可能错过两次采样之间的尖峰。P95 使用线性插值，本表用于同机比较；产线节拍需要在目标机器和实际负载下复测。[旧版逐组 CSV](../results/性能优化/release-before.csv) · [新版逐组 CSV](../results/性能优化/release-after.csv)

## 时间花在哪里

为定位 DLL 的开销，对 12 号样品额外使用 Release 插桩构建。同一进程交替运行两条路线各三次，分别记录以下三个区间的中位数。计时点位于 `ms_run_configured` 的开始、投票并行循环的前后和写入 `Result` 处。[分段原始记录](../results/性能优化/native-stages-12.csv)

| 路线 | 配准及准备 | 特征生成及森林投票 | 掩膜后处理及质量统计 |
|---|---:|---:|---:|
| 八波段，优化前 → 后 | 33 → 27 ms | 3240 → 155 ms | 163 → 158 ms |
| PCA，优化前 → 后 | 40 → 28 ms | 3522 → 366 ms | 166 → 194 ms |

两条路线的大部分收益来自特征与投票。PCA 仍会执行标准化、投影和局部布面估计。12 号样品的 PCA 后处理在本轮测量中略慢。全组 WPF 基准另记录 `read_ms`（八帧读取、解码、像素复制和固定）及 `preview_and_interop_ms`（扣除读取和 DLL 后的其余时间，含轮廓、位图和离屏渲染）。新版八波段两个区间的中位数分别为 81、33 ms，PCA 分别为 71、32 ms。

## 实现与调试

- **森林投票。** 加载 OpenCV RTrees 时整理一次数值分裂和叶节点。按 4 行构建局部特征矩阵，并行区间数上限为 12。通过 SSE2 同时比较 16 个像素，直接累计前景票数。模型结构超出快速路径的支持范围时调用 OpenCV `getVotes()`。用 `ms_score_rows` 和 `evaluation/check_votes.py` 可以独立对照逐像素得票。[投票实现](../native/forest_votes.hpp) · [OpenCV 4.5.4 的树遍历实现](https://github.com/opencv/opencv/blob/4.5.4/modules/ml/src/tree.cpp)
- **内存。** 随条带分配特征矩阵，连通域筛选提前释放距离图，掩膜后处理避免复制即将覆盖的全幅图。WPF 的透明背景、填充和轮廓使用三色 Indexed8 图层。当前分辨率下，每份轮廓像素缓冲由 19.125 MiB 减至 4.78125 MiB。显示所需的半透明颜色保存在调色板内。[原生后处理](../native/refine.cpp) · [WPF 像素处理](../desktop/Engine.cs)
- **操作响应。** 推理和 PNG 导出在后台执行。遇到批量取消，原生投票可在条带之间停止，后处理可在计算证据的行间和连通域阶段之间停止。若正在写出一个样品，先完成该组导出，再停止后续组。[WPF 调度](../desktop/MainWindow.xaml.cs)

**Debug / x64** 默认保留原生 PDB、调试运行库和 OpenCV Debug DLL，同时对项目的原生像素循环启用编译优化。12 号样品的读盘到预览实测，八波段由 121.55 秒降至 2.72 秒（重复一次为 3.52 秒），PCA 由 128.72 秒降至 2.99 秒。Debug 仅测该样品，未附加调试器。有些局部变量会被编译器消除，逐语句检查可在 VS Developer PowerShell 中按下列命令临时关闭优化。恢复日常配置时重新生成并省略最后的属性。[Debug 旧版记录](../results/性能优化/debug-before-12.csv) · [Debug 新版记录](../results/性能优化/debug-after-12.csv)

```powershell
msbuild PrintInspector.sln /t:Rebuild /p:Configuration=Debug /p:Platform=x64 /p:OptimizeVisionKernels=false
```

## 复测与结果一致性

在工程根目录执行。在目标设备上测量时连续完整运行基准，记录 CPU、配置和样品集合，保留 CSV 便于比较。

```powershell
.\build.ps1 -Configuration Release
dotnet desktop/bin/x64/Release/net10.0-windows/PrintInspector.dll --benchmark ../锐视光电 results/性能优化/local-release.csv
python -B evaluation/check_votes.py
python -B evaluation/check_abi.py
python -B evaluation/check_refinement.py
```

针对 8 组无膜片样品，已将两条路线各自的原始森林得分图及最终掩膜与优化前结果逐像素对比，全部一致。24 次 Release 测量的质量标志也与基准逐项一致。WPF 批量导出的 8 组 PCA 得分图、掩膜和叠加 PNG 解码后与基准像素一致。另验证了批量导出中的取消、控件恢复，以及非整块宽度、有行填充和不支持快速投票时的 OpenCV 回退。
